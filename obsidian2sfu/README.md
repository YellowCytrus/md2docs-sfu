# obsidian2sfu

Markdown из Obsidian → готовый DOCX по оформлению СФУ (СТУ 7.5-07).

Конвейер:

```
note.md (+ вложения)  →  note.txt (синтаксис V2)  →  note.docx
```

DOCX получает: титульный лист из `title_reference.docx` (с подстановкой ваших данных),
настоящее поле Word «Содержание» с отточием, нумерацию таблиц по разделам
(1.1, 1.2, А.1, Б.1 …), Times New Roman 14 pt, списки и таблицы как Word-сущности.

## Запуск

```bash
./obsidian2sfu "Универ/Моя работа.md"
```

* путь можно давать относительно хранилища (`--vault`, по умолчанию `~/obsidian_backup`)
  или абсолютным;
* результат кладётся рядом с заметкой (`note.docx` и `note.txt`), вложения копируются
  в `images/` рядом с результатом;
* по умолчанию дополнительно собирается PDF-превью (нужен LibreOffice).

Полезные флаги:

| Флаг | Что делает |
|------|------------|
| `--out PATH.docx` | куда сохранить (по умолчанию рядом с заметкой) |
| `--set key=value` | переопределить метаданные (например, `--set year=2027`) |
| `--sources-file FILE` | список источников (по одному в строке) |
| `--title-template PATH` | другой шаблон титульного листа |
| `--config FILE` | дополнительный JSON-конфиг |
| `--no-pdf` | не собирать PDF |

## Метаданные

Берутся по приоритету: значения по умолчанию → `~/.config/sfu/obsidian2sfu.json`
→ `<note>.sfu.json` (рядом с заметкой) → `--set`. Также читается YAML-frontmatter
заметки (`key: value`).

Ключи: `document_type`, `title`, `student`, `group`, `record_book`, `teacher`,
`institute`, `department`, `city`, `year`, `profile`, `language`.

## Настройка под конкретную работу

Рядом с заметкой создаётся `<note>.sfu.json` — только то, что отличается от общего
конфига. Полный пример (`*.sfu.json` эталонной работы):

```json
{
  "profile": "lab_practical_project_reports",
  "meta": { "title": "Моя тема", "group": "КИ00-00", "record_book": "000000000" },
  "sources": ["Источник 1", "Источник 2"],
  "ref_fixes": [["раздел 3.3", "раздел 2.3"]],
  "promote_to_h1": ["Показатели качества"],
  "kv_first_cells": ["Проблема", "Для"],
  "kv_captions": ["Постановка проблемы: ..."]
}
```

* `sources` — печатается как «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» перед приложениями;
* `kv_first_cells` — таблицы с такими значениями в первой ячейке идут без шапки;
* `kv_captions` — подписи для таблиц без `: подпись` в markdown (по порядку);
* `ref_fixes` — замены в тексте (если нумерация разделов сдвинулась).

## Что понимает markdown

Заголовки `#`…`####`, абзацы, маркированные/нумерованные списки, таблицы
(`: подпись` после таблицы — подпись), вложения `![[файл]]` и `![alt](путь)`,
блоки кода, цитаты. Введение/Реферат/Заключение/Список источников распознаются как
структурные разделы, `# Приложение N. Название` — как приложение (буквы А, Б, …).

## Зависимости

Проект `sfu_converter` (установлен в `.venv`), `python-docx`, LibreOffice и `pdftotext`
(`poppler-utils`) — для точных номеров страниц в содержании.
