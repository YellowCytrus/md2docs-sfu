# Обзор синтаксиса версии 2 и структура документа

Синтаксис версии 2 (v2) — рекомендуемый формат исходных файлов SFU Converter.
Каждый блок документа задаётся явным маркером в квадратных скобках, а его
параметры передаются атрибутами вида `ключ=значение`. Благодаря этому исходник
разбирается однозначно: парсер всегда знает, где начинается абзац, заголовок или
таблица.

## Главные правила

1. **Маркеры пишутся латиницей заглавными буквами**: `[H]`, `[P]`, `[TABLE]`.
   Кириллические двойники (`Н` вместо `H`, `Т` вместо `T`) ломают разбор —
   см. [Диагностику](v2-diagnostics.md#кириллица-в-маркерах).
2. **Весь текст обёрнут в маркеры.** Строка без маркера вызывает предупреждение
   (ошибку в строгом режиме).
3. **Атрибуты** — пары `ключ=значение`. Значения с пробелами берутся в двойные
   кавычки: `title="Обзор литературы"`.
4. **Парные блоки закрываются** своим маркером конца: `[TABLE]` → `[TABLE_END]`,
   `[LIST]` → `[LIST_END]`, `[SECTION]` → `[/SECTION]`.

## Синтаксис маркеров и атрибутов

```text
[МАРКЕР ключ1=значение ключ2="значение с пробелами"]
```

- Значение без пробелов кавычки не требует: `level=1`, `id=fig:overview`.
- Значение с пробелами или кириллицей — в кавычках: `title="Введение"`.
- Неизвестный атрибут просто игнорируется; неизвестный маркер даёт диагностику.

## Объявление документа `[DOC]`

Первая значимая строка файла. Задаёт версию синтаксиса, профиль и язык.
Все атрибуты, кроме `syntax`, попадают в метаданные документа.

```text
[DOC syntax=2 profile=lab_practical_project_reports language=ru]
```

| Атрибут   | Обязателен | Описание                                          |
|-----------|------------|---------------------------------------------------|
| `syntax`  | да         | Версия синтаксиса; для v2 всегда `2`              |
| `profile` | да         | Имя профиля оформления (см. [профили](v2-profiles.md)) |
| `language`| нет        | Язык документа, обычно `ru`                       |

Если `syntax` не равен `2`, парсер выдаёт ошибку `TXT_UNSUPPORTED_SYNTAX`.

## Метаданные `[META]`

Пара ключ-значение для титульного листа, колонтитулов и шаблонов. Каждый
`[META]` добавляет одно поле.

```text
[META key=title value="Отчёт по лабораторной работе"]
[META key=student value="Иванов И. И."]
[META key=group value="КИ22-01"]
[META key=supervisor value="Петров А. В."]
[META key=city value="Красноярск"]
[META key=year value="2025"]
```

| Атрибут | Обязателен | Описание                |
|---------|------------|-------------------------|
| `key`   | да         | Имя поля метаданных     |
| `value` | нет        | Значение поля           |

Без `key` маркер даёт ошибку `TXT_MALFORMED_ATTRIBUTE`. Какие именно ключи
обязательны — зависит от профиля (см. [профили](v2-profiles.md)). Часто
используемые ключи: `title`, `student`, `group`, `supervisor`, `teacher`,
`city`, `year`, `university`, `institute`, `department`, `discipline`,
`document_type`.

## Общий каркас файла

Типичный порядок блоков в учебном документе:

1. `[DOC ...]` — объявление.
2. `[META ...]` — метаданные.
3. `[TITLE_PAGE]` — титульный лист (см. [расширенные блоки](v2-extensions.md#титульный-лист-title_page)).
4. Структурные разделы: `РЕФЕРАТ`, `СОДЕРЖАНИЕ`, `ВВЕДЕНИЕ` —
   через `[STRUCTURAL]` (см. [текст](v2-text.md#структурные-разделы-structural)).
5. Основная часть: заголовки `[H]`, абзацы `[P]`, объекты.
6. `ЗАКЛЮЧЕНИЕ`, `СПИСОК ИСТОЧНИКОВ` с `[SOURCE]`.
7. `[PAGE_BREAK]` и `[APPENDIX]` — приложения.

Порядок структурных частей проверяется валидатором композиции
(см. [диагностику](v2-diagnostics.md)).

## Минимальный пример

```text
[DOC syntax=2 profile=lab_practical_project_reports language=ru]
[META key=title value="Разработка REST API"]
[META key=student value="Иванов И. И."]
[META key=group value="КИ22-01"]

[H level=1 title="Введение"]
[P] Цель работы — разработать REST API для управления каталогом товаров.

[H level=1 title="Заключение"]
[P] Поставленные цели достигнуты. Реализован полный CRUD.
```
