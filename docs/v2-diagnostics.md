# Диагностика и проверки

Парсер и валидатор сообщают о проблемах структурированными диагностиками: код,
уровень важности и место в исходном файле. Запустите проверку без генерации
файла командой `lint`.

## Как запустить проверку

```bash
sfu-converter lint --input report.txt --syntax-version 2
sfu-converter lint --input report.txt --syntax-version 2 --format json
```

Команда `convert` тоже выводит диагностику; флаг `--validate-output` дополнительно
проверяет получившийся DOCX.

## Уровни важности

| Уровень   | Значение                                    |
|-----------|---------------------------------------------|
| `info`    | Информационное сообщение                     |
| `warning` | Предупреждение, документ всё же создаётся     |
| `error`   | Ошибка, требует исправления                   |
| `fatal`   | Критическая ошибка разбора                     |

## Строгий режим

Флаг `--strict` превращает предупреждения в ошибки. Полезен в CI: документ не
соберётся, пока исходник не будет чистым.

```bash
sfu-converter lint --input report.txt --syntax-version 2 --strict
```

## Коды синтаксиса

| Код                       | Значение                                       |
|---------------------------|------------------------------------------------|
| `TXT_UNKNOWN_MARKER`      | Неизвестный маркер `[...]` или текст без `[P]`  |
| `TXT_DUPLICATE_ID`        | Один `id` использован на нескольких блоках      |
| `TXT_MISSING_BLOCK_END`   | Нет закрывающего маркера (`[TABLE_END]` и т. п.)|
| `TXT_MALFORMED_ATTRIBUTE` | Неверный или отсутствующий атрибут             |
| `TXT_INVALID_TABLE_SHAPE` | Разное число ячеек в строках таблицы           |
| `TXT_UNSUPPORTED_SYNTAX`  | Неподдерживаемая версия в `[DOC]`              |
| `TXT_CYRILLIC_IN_MARKER`  | Кириллические двойники в имени маркера          |
| `INVALID_HEADING_LEVEL`   | Уровень заголовка вне диапазона 1–4             |
| `HEADING_LEVEL_SKIPPED`   | Пропущен уровень заголовка                      |
| `TXT_IMAGE_NOT_FOUND`     | Файл изображения не найден                      |

## Коды структуры и оформления

Эти проверки выполняет валидатор композиции и правил профиля. Полный набор
велик; ниже — самые частые.

| Код                                  | Значение                                  |
|--------------------------------------|-------------------------------------------|
| `STRUCTURE_TITLE_PAGE_MISSING`       | Нет титульного листа                       |
| `STRUCTURE_REQUIRED_SECTION_MISSING` | Отсутствует обязательный раздел            |
| `STRUCTURE_SECTION_OUT_OF_ORDER`     | Нарушен порядок структурных частей         |
| `STRUCTURE_APPENDIX_BEFORE_SOURCES`  | Приложение раньше списка источников         |
| `HEADING_POINT_REQUIRES_SUBPOINTS`   | У пункта только один подпункт               |
| `FIGURE_NEVER_REFERENCED`            | На рисунок нет ссылки `[REF]`               |
| `REFERENCE_UNRESOLVED`               | Ссылка на несуществующий `id`               |
| `BIBLIOGRAPHY_MISSING_FIELD`         | В записи источника нет обязательного поля    |
| `FOOTNOTE_UNMATCHED_ANCHOR`          | Якорь сноски без тела                       |
| `FOOTNOTE_UNMATCHED_BODY`            | Тело сноски без якоря                        |
| `PROJECT_DESIGNATION_FORMAT`         | Неверный формат обозначения проекта         |
| `TXT_MISSING_METADATA`               | Не хватает обязательных метаданных профиля   |

Коды начинаются с префиксов по областям: `TXT_` — синтаксис, `STRUCTURE_` —
композиция, `FORMAT_` — оформление, `HEADING_`, `FIGURE_`, `FORMULA_`,
`BIBLIOGRAPHY_`, `CITATION_`, `FOOTNOTE_`, `REFERENCE_`, `APPENDIX_`,
`PROJECT_DESIGNATION_`, `STYLE_`, `GRAPHIC_`, `POSTER_`, `SLIDE_`, `TOC_`.

## Кириллица в маркерах

Маркеры пишутся **латиницей**. Кириллические двойники (`Н` вместо `H`, `Т`
вместо `T`, `Р` вместо `P`) выглядят одинаково, но ломают разбор. Парсер
сообщает об этом кодом `TXT_CYRILLIC_IN_MARKER`.

Проверить и исправить файл:

```bash
python -m sfu_converter.tools.check_cyrillic_markers
python -m sfu_converter.tools.fix_cyrillic_markers
```
